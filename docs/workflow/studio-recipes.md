# Studio 操作配方与组合顺序

> 费用：任务范围内默认自主使用现有 Studio 积分，按项目 docs/workflow/credit-policy.md 执行，不逐次请批。参考/质量审阅、本地返工限制、未知任务对账仍保留。

按目标读取一个配方，配合 [功能选路表](studio-capabilities.md)。以下选路与检查是本项目制作规范；官方宣称的质量、速度、免费额度不能替代当前页面与实际输出。付费/试用任务沿用 preflight→generate 的一次提交及未知对账；不会因为按钮叫“预览”“重试”“应用”就跳过记录。

## 先分类，减少返工

先看已存在结果能否直接满足需求；合格就跳过该处理。缺陷分为参考身份、几何、组件、拓扑、UV、底色、分辨率、PBR、绑定、动作语义、传输/导入。只修改对应层及必要依赖。

| 变更 | 后续必须重新核查 |
|---|---|
| Mesh Edit / 补全 / 风格化 / 重拓扑 / 改分界 | 轮廓和保护区、对象/顶点/拓扑、UV/纹理、蒙皮/骨架映射、动作与导出；不能假定“局部”保持顶点顺序 |
| Smart UV / 换UV | UV布局、原纹理能否正确重烘焙/生成、所有通道及导出；网格/骨架也检查是否意外改变 |
| Texture Gen / Brush / Upscale | 颜色身份、接缝、PBR一致性、通道尺寸/色彩空间、导出材质；若实测网格和UV未变，不无故重绑 |
| Auto Rig / 改权重 | 骨名/层级/rest pose、所有受影响clip、接触和保护区、导出回读 |
| 新动作 / 多阶段动作 | 节奏、动作语义、穿插、root、循环/过渡、动画导出；不自动否决无关静态合格结果 |
| 格式转换 / 压缩 / Bridge | 单位、轴、pivot、对象、UV/材质、骨架/clip清单、接收文件身份 |

正式拓扑、UV和绑定的依赖与早期诊断分支分开：需要时用Tripo试绑及动作暴露结构问题，已知结构缺陷可先修，不强制先付费试绑。稳定结构需要重新进入Studio时上传交换副本，最终权重和动作精修留在最后一次必要往返之后；试验蒙皮不直接套回改过拓扑的母版。新增正式贴图仍受当前源动画preflight约束，详见 [往返规范](roundtrip.md)。

## 1. 参考在前，模板按问题选择

用 R01–R09。原图可用先保留；多主体用 Asset/Character Extraction 与 Cutout 候选方案，缺身体用 Completion，绑定姿态有问题才评估 T Pose，近景人脸可独立研究 Head Extraction。不要为了工具能力把整个角色拆成难以装配的零件。模板后的比例、接口、身份和新设计都重新审阅；四视图应从同一已选概念派生，不分别随机生成。

Studio Image Gen 是可用方案，模型、比例、数量和费用以当次UI为准；并非必须使用。遵循当前会话的生图工具规则：默认内置 imagegen；用户明确选择Studio生图/编辑且授权覆盖时再用Studio。已有生图选择复用；适配支持的Studio图像操作使用持续积分授权，参考图最终审阅仍保留。

**当前适配边界**：执行器的远程 run 要求已批准建模参考，因此不能伪造最终参考批准来执行更早的Studio生图任务。当前没有独立的Studio参考生成提交账本；该收费分支保持待适配。具备已批准参考的后续3D处理可走现有执行器。研究中的Studio参考模板不被误标为已自动化；本轮优化不更改已有工具优先规则。

## 2. 新模型选型与候选策略

用 G01–G09。游戏/实时资产先评估P系列；近景高细节和打印母版评估H系列。判断依据是目标屏幕占比、轮廓、活动结构、可编辑性及后续接口，不是“越新/面数越高越好”。记录三角/四边单位，目标引擎最终预算看三角化实际结果。

预计要拆分时提前决定：H可检查分部件生成，P2检查原生分件是否满足；如果必须后拆，当前拆分页排除四边和已绑定输入，需选择兼容的未绑定源分支。不能为了走拆分按钮静默丢掉已经合格的四边拓扑和Tripo绑定。

只要需要改几何/UV，优先完成这些再做最终高分辨率材质。若静态一次生成已全合格，直接检查和交付；不要重新走全部后处理。

**批量与变体区别**：Multi-Views＝一个主体多角度；P2变体＝同一设计多个面数结果；Batch＝多个资产；动画多阶段＝一个动作的时间节点。禁止互相代替或混用计数。

当前 `candidate_count=1` 仍由代码强制，保留预算恢复语义。已有多输出的历史任务只读恢复、逐件核对，不重提。未来启用远程批量/多变体前需实现父任务→子输出身份、总报价只计一次、部分完成/失败/未知对账、逐输出选择与验收，并测试恢复；不能把UI中的2/4输出偷偷记作1。现可在授权范围内按单资产单run串行制作，每个都有独立报价；不得宣称享有多变体同价优惠。把多变体列入需求相关的候选方案并报告当前限制，而非忘记平台有此能力。

可复用参数检查顺序：输入文件/视角槽→P或H及实际模型版本→几何/纹理模式→部件→三角/四边与目标面数→增强/纹理分辨率/去光→输出数量→隐私→总报价。只填写当前入口实际支持的项；切换模式后重读全部受影响设置，不能用一套固定H参数覆盖P。

## 3. Mesh Edit、拆分、补全与拓扑

Mesh Edit（M01）：当前模型查看器核实入口和支持版本→保存源分支→锁定缺陷及保护区→调整选择框→检查多角度实际范围→核实 Retry Selection/Regenerate 含义及报价→单次处理→比较局部连接、轮廓和区域外属性。页面只有预告时记unknown；不推定后台API可用。整体身份错回参考，少数精确尺寸问题可比较Blender局部修正成本。

拆分（M02–M03）：先列出最终需要的组件，选择最少足够的粒度；已有分件合格就跳过。选择兼容的未绑定输入，拆分后用不同颜色定位错分界，按当前UI Brush/Add Part/Merge修正并确认。零件重命名，记录装配transform、枢轴意图、材质边界、遗漏及碎片。连续软组织不因为“能拆”就切成机械关节。

补全（M04–M05）：检查切口是单纯开放边界还是确有缺失体积；前者评估Quick Cap，后者评估AI Completion。仅选目标部件，保持其他组件位置和接口。封口/补全后检查穿插、自交、法线和薄壁；需要打印的部件逐个检查闭合。官方免费说明只作发现线索，使用次数与导出次数也核实。

拓扑（M06–M07）：轮廓合格后，按需要重做全模或受影响部件。实际源显示哪个算法就记录哪个，不能把重拓扑面板P1.0写成生成模型P2.0。保护眼口、关节、薄边和硬表面轮廓；比较减面前后，而非看目标面数即通过。若原生P2已经符合要求，不追加机械式减面。每个LOD是独立候选，必须验证位置/材质/骨架兼容和实际切换。

## 4. Smart UV 与原始 UV 的取舍

M08–M09用于UV缺失或明显不合格；有良好UV和贴图时先保留。Smart UV当前文档与入口均为≤80,000三角或≤40,000四边；绑定源是否完整保留骨架另核。超上限优先使用兼容的低模分支，不覆盖高模母版。

冻结几何版本→选择已有模型或上传稳定文件→核对UV重建会影响哪些通道→读取报价/试用→展开一次→联动点击UV岛/模型面定位接缝→检查利用率、拉伸、密度、重叠与间距→保存可比较版本。利用率高但脸部接缝/拉伸更差时拒绝晋升。重试只针对明确问题，不以刷高百分比为目标。导出回读UV后再做正式贴图；不得把旧贴图直接贴到新UV而称为保留材质。

外部贴图/Upscale若有 Use Original UV，只有确实需要保留且UI支持时使用，回读确认未重展；看见开关不等于网格、UV、骨架或形态键全都保留。

## 5. 纹理分层处理

默认判断顺序：几何和UV已稳定→已有底图是否合格→必要的全局Texture Gen/风格参考→局部Magic Brush→需要时Upscale→核对/补齐与当前底图一致的PBR→回读。已有完整PBR且无内容改变可跳过独立生成。

全局（T01–T03）：无底图用图片或材料区域提示；整体风格错才全局重生。真实重新打光资产检查去光处理，手绘阴影属于设计时保留相应风格。不能在原图要求不变时用风格迁移自行换色。

局部（T04–T05）：从正对目标面的角度开始；按实际UI核对相机锁定/解锁、生成或绘制模式、强度、预览及刷选。预览生成可能收费；记录其任务、返回预览和后续保存，不能把“生成预览→应用→保存”盲目重复成多轮重生。比较选区边界、背面/遮挡和保护区；无法可靠刷选时交互请用户选区或改用受控局部工具。Brush不修几何，也不保证更新metallic/roughness/normal。

放大（T06）：只对最终采用的纹理放大；先修错图案和接缝，再比较相同机位的近景。选择满足最终观看/显存预算的最小分辨率；8K不是每个资产默认值。官方8K导出说明区分8K BaseColor与4K Normal/ORM；报告逐贴图实际尺寸，不能标成“全通道8K”。

PBR（T07–T08）：检查BaseColor、Normal和ORM/独立通道实际内容与目标引擎解释，区分缺贴图和导入节点错。只有所需通道缺失或不一致才生成；在中性照明和目标材质中复核粗糙度/金属度/法线。转换和预览的PBR开关不能替代文件检查。

局部修色提示示例（按实际选区改写）：`仅将选中的左肩护甲改为哑光橙色，保留原有接缝和编号；头盔、胸部、右肩、轮廓和光照风格保持一致。` 保护要求同时写入前后对照，不能因提示中写了“保持”就默认没有漂移。整体纹理提示则按区域列出材料，例如外壳涂漆金属、关节橡胶、面罩玻璃，避免只有“高质量、真实”等无法验收的描述。

Stylization（T09）是设计分支，不是最终通用精修。先确认用户需要相应风格及当前入口；Voxel/LEGO会改变形状、薄件和关节，应放在最终拓扑/UV/绑定前。当前找不到入口记unknown，不能依据旧文档擅自模拟点击。

## 6. 原生绑定、预设、文字/视频与多阶段动作

先逐clip明确动作、起止姿态、朝向、左右手、接触、速度/时长、循环与root。骨架必须来自Tripo；保留原生版本，先排除导入/NLA叠加问题。非标准形体需检查当前支持类型，不能引用“任意生物”宣传替代适配检查。

外部模型路线：先完成必要结构修正，保留母版，上传稳定交换副本；核查当次输入兼容和报价，再按需执行原生绑定。页面显示“已绑定”不证明外部精修权重和旧动作保留；新绑定后核对当前骨架、蒙皮和实际动画通道，再建立当前rig/motion证据。已有同版本合格结果可跳过上传或重绑，不能为新增动作默认覆盖旧精修内容。

1. A02：搜索语义及近义词，按分类/最近使用查已有动作；候选预览符合需求再应用。应用/预览可能生成任务，先核实。已有源clip能用就不重生。
2. A03–A05：无匹配预设再评估专属动画。文字描述具体身体行为；视频只使用用户提供/授权的参考，读取当次格式和时长要求，不臆造视频输入限制。连续行为优先评估多阶段：逐节点填写动作/时间，明确接触和朝向，先最小节奏草稿再精修。单个动作不强制拆节点。
3. 多阶段当前UI说明为生成后再应用。分别记录生成任务、结果预览、选中结果与应用后的模型版本；先核查应用是否另计费/创建任务。不要生成完成就宣称模型已带该动作。
4. 检查完整clip、过渡、手脚语义、root、脚滑和自交；实时与慢放、正侧面/接触近景配对。节奏草稿按原协议交真实用户确认。
5. 预设不匹配且专属动画失败/经核实不可用时，才在Tripo骨架上本地制作；只修接触/幅度/朝向可局部处理，不无故重做整套动作。

A07用于静态姿势：锁定选中帧导出求值后网格，另存姿势分支；打印检查仍需执行。动画交付在实际导出面板明确选择骨架、所需clip及其数量、材质和格式，再在干净场景逐一回读。2026-10-02本项目测试默认选中0个动作；以后按当次UI检查，不把预设正在播放视为已选导出。回读查实际骨骼通道、时长、root、Action slot/NLA及完整播放，不把锁帧网格或同名空动作当动画交付。

动作描述示例（不是固定参数）：`角色原地站立，面向前方；右手抬到肩侧，掌心向前挥动两次后放下，左臂自然垂下，双脚保持接触地面，结束回到起始站姿。` 需要“转身→挥手→坐下”时拆为有序节点，逐节点定义朝向、支撑和时间；具体秒数先依据用户节奏或草稿确定，再填UI，不能用文本描述代替实际时长设置。

## 7. 资产历史、导出、Bridge与配套工具

Assets/History先用于复用、对账和分支；记录task、版本、parent及输出哈希。高影响编辑先另存/复制；恢复旧版本也要重新选择当前候选与证据。不能把历史UI的“恢复”当成撤销费用。共享、画廊推荐及自动发布只在明确授权范围内执行；AI生成宣传图另标展示图，质量报告用真实模型证据。

导出前列出所需对象、单位/轴/pivot、UV、贴图通道、骨架及明确选中的clip。使用Studio Bridge优先发送同版结果；格式属性对比、独立归档或Bridge不可用时采用文件路线并记录原因。保留接收回执、可编辑母版和哈希，未知先对账，不因传输失败重生。外部模型返Studio先核实当前上传条件，格式支持不等于属性无损；交换副本与返回结果另存，比较几何、UV、材质参数、骨架/权重和实际动画。最终本地精修后才正式导出及验收，不能自动双向覆盖，详见 [往返规范](roundtrip.md)。

Viewer/Converter/Compressor用于派生副本的格式和体积优化；记录是否改了几何或贴图，压缩结果在目标加载器中验证。打印才接入STL Repair/Editor、锁定帧、Bambu Bridge；检查尺寸、薄壁、闭合、自交、方向和支撑，发送切片器不等于实际打印。API、CLI、Team管理与网页制作分账，本项目仍不自动切换后端。

## 推荐组合（只执行相关且未满足的步骤）

| 目标 | 优先组合 | 省时点 / 退出 |
|---|---|---|
| 游戏道具 | 适用单图/四图→P系列→必要Mesh Edit→必要UV/纹理→Bridge→引擎 | 合格原生拓扑跳过重拓扑；纹理只在最终候选放大 |
| 动画角色 | 适配参考→P/H及部件计划→必要结构修正→需要时上传交换副本→Tripo绑定/目标动作→导回预检与节奏确认→最终权重/材质/动作精修→回读 | 早期试绑可选；合格结果复用，改拓扑或重绑后不继承未经核验的旧蒙皮/动作 |
| 模块化机械/装备 | 预分件或兼容源拆分→边界修正→按需封口/补全→局部拓扑→UV/材质→装配 | 不为已分开的正确组件重复拆分；明确刚性与蒙皮区域 |
| 近景产品/手办 | H高细节→必要局部修形→UV→参考纹理/去光→Brush→适用8K/PBR | 保留几何，只提升短板；最终实际观看距离验收 |
| 打印姿势模型 | 结构参考→H或适用P→可选Tripo动作锁帧→分件/封口→尺寸与切片 | 无纹理需求可跳纹理；按既有明确选择，无需反复询问 |
| 系列场景资产 | 提取/选定参考→逐资产生成→复用材质风格→Bridge装配 | 参考批量与3D批量区分；当前按单run执行，批量提交待适配 |

## 成本与结果记录

在现有路线/运行报告中补充实际生成、等待、检查、修正时间，页面报价与实际费用（未知保持unknown），使用功能ID、输入类别、失败原因、保护区退化和用户返工。比较“每件验收通过资产”的总成本/总耗时，而非按钮次数或功能覆盖率。未实测不填预计节省百分比；同一策略连续两轮无改善沿用现行停止规则。

在既有 `generation-route-vNNN.md` 复用以下最小记录结构（领域说明，不替代正式plan schema）：

```text
目标/源身份：用途、源run或Studio版本、本地hash（可用时）
缺陷与保护：哪一层不合格；哪些对象、区域、UV、骨架、clip必须保留
选路：功能ID；采用/已满足跳过/不适用/输入不兼容/unknown及证据
准备：当前输入限制、实际控件设置、报价、既有授权引用
操作阶段：提交/预览/应用/保存各自身份；未知状态与对账结果
结果：新run/版本/hash；实际变化；受影响关卡及回归证据
退出：通过条件；失败原因与下一条可行路线；实际费用/耗时
```
