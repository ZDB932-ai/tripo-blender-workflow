# Tripo Playwright 操作规范

适用于当前项目的独立 Chrome 与 tripo_playwright；通过真实 Studio 网页操作，使用已授权的网页额度。不自动切换 API 或换登录身份。环境配置见 [PLAYWRIGHT_SETUP.md](../../PLAYWRIGHT_SETUP.md)。

## 每次操作的顺序

1. **观察**：检查当前 URL、资产/版本、面板及 DOM/可访问快照。页面导航、模式切换、弹窗或任务完成后刷新观察，不复用旧元素引用/坐标。
2. **定位**：优先角色、名称、标签，并限定所在面板；提交或开关必须唯一匹配。多个匹配时继续定位，不能用 first() 猜测目标。画布操作依据当次边界，仅在必要时使用坐标。
3. **分类**：确认动作是只读、改设置、上传、创建任务、传输或付费。预览、动作预设、试用及 Brush 保存等名称不代表免费；行为不明先查清。
4. **执行一次**：有必要的范围、计划和额度依据后执行。提交前 check-plan → mark submitting 落盘 → 再点击一次。Bridge 用独立 sending 记录。不要把付费操作放入自动重试循环。
5. **核验后置状态**：读取实际选中值、任务身份/进度或下载事件；点击成功不等于设置生效，更不等于模型生成成功。
6. **留证**：记录设置、报价、身份、时间、必要截图和错误；结果未知先对账，不以按钮还可点击为重试依据。

## 选模式与模型

先用当前需求和动画用途比较模式，再检查当前账号真实可选的模型/版本、单图/多图入口、功能限制和报价。能力资料仅作候选依据，不能照抄旧名称、官网价格或历史选项；没有确定性选型算法，不伪称自动最优。

切换模式/模型后重新读取输入槽、几何、面数/拓扑、AI 增强、纹理/PBR、分件、隐私、候选数量、试用状态和报价。只填当前页面实际支持的字段，缺少关键功能就报告。绑定用途影响选型理由和结构检查，不能以高面数或四边面标签代替可动性证明。

保存 plan.settings 和独立 ui_verification 文件引用。ui_verification 包含：reference_manifest_sha256、intake_sha256、operation、observed_at、quoted_credits、page_url、target_description、selection_reason、unique_target=true、settings_match=true、actual_settings、animation_use、evidence 文件引用数组。actual_settings 必须与 plan.settings 完全一致；生成计划至少含当次可见 mode/model。值来自操作后的页面，不把计划字段复制成假观察。

图片生成另记录 uploaded_files 文件引用数组和 input_layout，确认实际预览的文件、朝向、数量及入口；上传文件须属于当前已批准参考且非 qa-only。三视图拼版不能假定等于多槽输入。模型后处理按 typed input 固定输入文件/Studio 版本，不强迫重新上传参考图。

报价核对时间须与计划相同，现有代码拒绝过期 30 分钟或异常未来时间；即使未过期，点击前发现参数/余额/价格变化也须更新具体计划及有效授权绑定。选择理由应明确静态/未来动画/纯绑定/具体动作对本次模式的影响。

## 失败与恢复

- 一个 profile 同时只由一个任务持有。登录/验证由用户完成，不删除占用目录、不杀所有 Chrome、不以新身份规避验证。
- 网络问题用已有页面/资产做只读诊断，不点击生成测试连接。MCP 外层成功还须检查正文。
- submitting 或通信中断：查任务列表、时间、输入、资产身份及余额证据；找不到一次不证明没提交。保持未知，不再点击。
- 已生成但预览/CDN 失败：恢复同一个结果。下载失败：先查实际落盘，再恢复同一版本，不重新生成。
- 下载前注册事件监听，再点导出；saveAs 后检查 failure、大小、格式、依赖和哈希。
- 页面发生意外跳转、目标不唯一、设置对不上、报价未知时停止依赖操作，继续允许的只读诊断。相同失败无新增证据不反复重试。
- 不关闭证书校验、不读取登录密钥，不保存 cookie 或签名下载 URL 到共享报告。

这些是代理操作规范与本地提交检查，不是拦截所有浏览器点击的沙箱。CLI 校验快照身份和记录一致性，仍由执行者实际观察页面与遵守单次提交。

## 功能上下文与多步操作

按 [Studio功能表](studio-capabilities.md) 定位相关功能，打开具体源版本的面板后再判断兼容；空面板、宣传入口和已有模型可操作是三种不同观察。旁边的“生成模型”设置可能指下一次生成，不能作为当前查看模型的来源证明。

预览生成→选中预览→区域应用→保存、多阶段动画生成→预览→应用，分别核查后置状态及是否创建任务。一个已提交任务的后续保存不是再次生成的理由；若某步另收费，须使用相应计划和有效授权。完成后记录输出版本和实际文件，不仅记录按钮。

只读研究可打开空面板、已有模型和设置；不要为暴露更多按钮生成、重绑或修改源。UI不支持quad/rigged等当前输入时回选路，不通过改格式名、编造拓扑类型或删除骨架来绕过。切模型/模式/输入后刷新控件证据，限制与报价按当次UI，研究记录不能直接作为未来提交依据。

## 统一会话恢复规则

默认唯一入口为现有 tripo_playwright MCP 持久会话。先读取 tabs/snapshot，正文中的 Transport closed 也算失败；不得为一次检查另起 headless 或临时 profile。`tools/playwright/recover-export.mjs`、`recover-smart-download.mjs`、`inspect-recovery.mjs` 已停用，历史内容仅供追溯。

| 当前情况 | 恢复动作 | 何时继续 |
| --- | --- | --- |
| 会话可用、页面正常 | 复用当前会话，核对目标资产和版本 | 新快照身份匹配 |
| Cloudflare/登录页 | 保持现有窗口和 profile，请用户在该会话完成验证；不自动刷新、清 cookie 或重启 | 用户完成后在同会话读取页面，确认验证页消失、目标版本可用 |
| 用户正在独立登录窗口操作同一 profile | 不争抢 profile；只有确实需要把所有权交回 MCP 时才请用户关闭该独立窗口 | 原持有者退出且 MCP 接回成功；不要把关闭窗口作为每次验证的固定步骤 |
| Transport closed | 先核对待提交/传输状态与文件；确认原会话是否仍活着。能重连则重连 | 无法重连时，确认原 owner 已退出后仅启动一次原 MCP 配置；不以新脚本替代 |
| profile 被占用/owner 未知 | 停止新启动，检查 owner；不杀用户浏览器、不删除锁文件 | 所有权明确 |
| 已提交但状态未知 | 只读对账任务、来源和落盘文件 | 正常工作流对账完成后才允许下一个依赖动作 |

一次恢复失败且没有新证据就保持现场并报告，不反复启动/关闭。任务完成不例行退出账号、关闭浏览器或清理 cookie。记录恢复原因、会话入口、目标资产/版本、待对账操作及验证结果到当前 work 恢复记录，不记录凭据、cookie 或签名 URL。此规则约束代理行为，不声称提供跨所有进程的自动互斥锁。
