# Blender与Tripo的交换及动画顺序

用于动画资产需要结构修正、外部模型上传或新增原生动作的路线。静态任务、同版下载和无需重绑的纹理小改跳过不适用步骤。本文是协议3.6的选路说明，不新增状态、制作预算或审批关卡。

## 默认路线

**Tripo基础制作 → 检查并完成必要结构修正 → 交换副本上传Tripo → 原生绑定与目标动作 → 导回Blender检查 → 最终权重、材质、动作精修 → 正式导出。**

结构问题优先评估适用的Studio分件、补全、拓扑或UV功能；Blender处理有明确理由的局部修正。没有结构问题就不增加修整。已有同版本合格Tripo骨架和目标动作可直接复用，跳过再次上传/重绑。早期动作试验是发现结构缺陷的可选分支，不要求每个角色先花积分绑一次再修结构。

最终精修放在最后一次必要的Tripo往返之后。若之后再改拓扑或必须重新绑定，先记录会受影响的UV、权重和动作，再按实际变更重测；仅改颜色且几何、UV、骨架不变，不启动整个循环。

## 1. 稳定结构，保留母版

- 先核查轮廓、关节空间、部件接口、拓扑和UV；仅修影响目标用途的真实缺陷。分件和拓扑处理在绑定前安排，Smart UV在拓扑稳定后安排。
- 保留可编辑Blender母版和来源哈希。交换文件另存，回传文件另存；上传、自动绑定或下载结果不能覆盖已验收母版。
- 上传姿势使用当前页面接受的中性T/A等姿态，核对实际静止姿势与坐标，不把正在播放某个动作的变形误烘焙进结构。不为“清理”盲目删除骨架、应用变换或烘焙所有修改器。
- 独立装备保留对象身份、装配坐标及预期随动方式。独立网格不等于刚性绑定；附件是否参与自动蒙皮，以回传结果核查。

本地结构修改仍走work start/finish和原预算；只读检查不计作修复。绑定前不需要提前把将被重新生成的权重、动作或材质细节全部精修完。

## 2. 制作交换副本并核对上传

从已保存母版制作GLB/FBX等**交换副本**，按当前Studio实际支持的格式、大小和输入条件选择。GLB适合嵌入贴图和记录动画；格式能力不等于服务会无损保存所有输入属性。保留母版、交换文件、设置与哈希，不把交换副本标作正式交付或export_verified。

在现有路线/传输记录中复用以下内容，无需另建全功能审批表：

| 属性 | 上传前记录 | 上传及回传后核查 |
|---|---|---|
| 几何与组件 | 对象名、面数、装配关系、需要保护的轮廓 | 部件是否独立、接口/轮廓、删面与合并；顶点重排不能仅靠hash判变形 |
| UV | 使用的UV层、接缝与贴图对应 | UV是否存在、布局和纹理映射；存在不等于无损 |
| 材质 | 材质槽、纯色参数、基础色/法线/金属粗糙度等依赖 | 是否合并材质、遗漏参数/通道、改变图片或资源路径 |
| 骨架与权重 | 骨名/层级/rest pose、蒙皮对象与附件刚性意图 | 是否沿用或重新生成，骨骼映射与实际变形；骨数/归一权重不是质量证明 |
| 动画 | 所需clip、时长、root策略、应保留的旧动作 | 实际骨骼通道、完整播放、节奏、root及循环；名称存在不能证明动作保留 |
| 场景与尺度 | 单位、轴向、pivot、对象变换 | 坐标转换和装配位置，避免把导入映射问题当模型缺陷 |
| 来源 | 母版及副本hash、Studio资产与任务版本 | 逐步关联输入与结果，不把旧模型检查迁移到新版本 |

只有本次需要保护或改变的属性才展开检查；不适用项写明原因。文档承诺、UI识别、实际执行和质量通过分开记录，未知属性保持unknown。

纯格式转换属于传输准备，不能顺便改几何、材质或权重来绕过制作批次。正式最终export的前序质量要求保留，详见[请求范围](request-modes.md)。

## 3. 在Studio绑定并生成目标动作

外部模型上传后，即使页面显示“已绑定”，也不据此推定已有精修权重、旧动作或原生预设兼容性完整。先检查可用结果；确需原生新绑定时，按preflight/generate核查输入、当前报价和已有授权，提交一次并保存真实回执。

新绑定可能替换骨架、权重和动作。保持旧精修内容是明确要求时，先保存它们，评估在独立分支生成动作再映射回母版的可行性，不能默认重绑覆盖。该映射必须实际验证，不能承诺直接复制Action即可。费用和改变范围已有授权就继续，不因换软件重复询问。

动作仍按明确需求→匹配预设→专属文字/视频/多阶段→最后才在Tripo骨架上本地制作的顺序选用。先用一个相关片段核对新输入/新格式兼容；已有同版本有效证据直接复用，不为每个预设重复试验。正式目标动作的节奏草稿与用户已授权的扩展动作范围分别处理。

点击没有反馈时先区分未就绪、未应用和未知提交，核对页面/任务回执，不重复点击或自动重绑。未知收费状态按原[恢复协议](../../tools/workflow/RECOVERY.md)处理。

## 4. 显式选择动作，再导回核对

打开实际导出面板，检查骨架开关、**已选动画数量及具体clip**、纹理、格式、原地/位移选项。2026-10-02本项目测试中，Studio动画导出默认选中0项；不能把正在播放的预设当作已选导出动作。以后按当前UI核查，不固定套用该默认值。

同版传输沿用Bridge优先；需要格式属性对比、独立归档或Bridge不可用时采用文件路线并记录原因。先确认接收场景，未知发送先对账。传输失败恢复同一任务，不重新付费生成。

回传先在独立场景只读检查：对象/UV/材质和依赖、骨架层级及蒙皮、clip清单/时长/实际骨骼通道、Action slot/NLA、坐标尺度和完整播放。root按动作用途核查：原地鞠躬不因缺少额外对象根通道就判缺失；有位移动作另核根运动。需要精确定位导入差异时，可比较同一时刻的原文件节点动画与Blender回读；无需给所有资产强加本案例采样数量或容差。

外观图、骨骼数、动画名称及任务success分别不能代替实际回读。图片内容相同不等于材质参数/UV也相同；归一权重不等于附件不会弯曲。播放设置排除后再决定是否修源模型，详见[导入排错](import-and-presentation.md)。

## 5. 最后精修和正式验收

根据回读缺陷，在保留Tripo骨架来源的版本化副本上局部修权重、关节和接口、材质/贴图、动作曲线/接触/过渡。硬质背包等附件出现实际变形时，采用与躯干骨骼匹配的刚性随动或刚性权重，再核对装配；柔性附件按设计处理。不要求所有装备都修一次。

新绑定不是旧rig/motion验收的延续。源版本改变时重新建立当前检查或按已有依赖指纹证明可复用的部分；不能只继承同名骨骼/clip。正式本地polish→rig→motion→final的关卡、权重保护、节奏确认、预算和停止条件仍按[执行协议](../../tools/workflow/PRODUCTION.md)与[动画规范](animation-review.md)执行。初期Studio试绑/试动作是远程run；隔离diagnostic可先于正式关卡，不能冒充最终rig/motion通过。

正式导出逐clip回读并验证依赖与实际播放。交换文件、原生动作回传和最终精修交付分别标注。完整动作/格式尚未测试时说明范围，不用单个片段通过推断全部动作合格。

## 本项目证据范围

星际维修员往返测试（本地历史资料，未随包分发）：2026-09-29至10-02，这个GLB上传—原样导出改变材质/权重，旧17个动作只剩根对象通道；重新原生绑定后，新6秒鞠躬导回Blender可播放、采样骨骼位置对照通过，背包出现非刚性变形。证据支持上述分阶段路线，不支持所有外部格式/骨架无损往返、所有动作自动合格或每次必须重绑。

官方[外部模型动画说明](https://www.tripo3d.ai/help/features/is-it-possible-to-upload-my-existing-model-for-animation)和[DCC导出说明](https://www.tripo3d.ai/help/features/how-to-export-and-import-to-dcc-tools)作为能力来源；输入兼容、参数和费用仍以当前页面及本次结果为准，不把API参数当Studio控件。
