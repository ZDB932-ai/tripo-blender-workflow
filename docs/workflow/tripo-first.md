# Tripo主生成、Blender辅助修正

适用于本项目的Tripo资产工作流。用户明确只做本地编辑、禁止远程调用或指定其他路线时，遵从其范围。本规则改变默认选路，不扩大授权，不改变现有执行器的状态/预算schema。

## 职责和默认顺序

Tripo负责内容生成：几何、纹理、适用的结构处理、自动绑定及目标动作。Blender负责导入核验、压力测试、精确局部修正、交换格式与最终回读；不因已导入Blender就默认重做骨架、权重、材质或程序生成整套动作。

默认：需求确认 → 按复杂度选择参考并审阅 → Tripo基础制作 → 完成必要结构修正 → 需要时上传稳定交换副本 → Tripo原生绑定与目标动作 → Blender导回检查 → 最终权重、材质和动作局部精修 → 正式导出/回读/验收。已有同版本合格骨架和目标动作直接复用；静态任务跳过绑定和动作。具体交换、属性保留及检查顺序见 [往返规范](roundtrip.md)。

“充分利用”指优先使用与目标相关且已核实可用的功能，不是每个功能都点一次。保留合格结果，不强制重新生成、重复纹理或在无可靠输入入口时上传Blender文件。

具体功能与顺序以 [Studio功能表](studio-capabilities.md) 和 [操作配方](studio-recipes.md) 为准。新制作至少评估目标相关的参考准备、生成模式、部件/拓扑/UV、纹理层次、绑定/动作、导出路线；只记录适用项的采用或跳过依据。当前分割入口排除四边/已绑定模型，需先规划组件；Smart UV放在稳定拓扑之后、最终贴图之前；局部颜色、分辨率、PBR问题分别处理，不能统一重生全模。需要通过动作暴露结构问题时可提前试绑和隔离诊断；不要求先付费试绑再修已知结构缺陷，不把试验骨架直接套回改变拓扑的正式母版。当前源的动画preflight要求仍有效。

## 开始内容制作前的选路记录

完整生成任务及准备在Blender新建/替换内容时，在资产work/下保存版本化的`generation-route-vNNN.md`，并在本轮计划的hypothesis/authorization_evidence或现有证据字段引用它。只读审计、同版下载和明确的小范围修正不必为此另建计划。

记录以下内容，已有同源事实复用：

| 项目 | 必须说明 |
|---|---|
| 目标与来源 | 本次交付、源版本/哈希、需要保留的设计/骨架/动作 |
| Tripo能力 | 对应页面功能、输入兼容性；available / unsupported / unavailable / unknown；当前UI或实际任务证据 |
| 已尝试结果 | run与产物、实际缺陷；未尝试时说明原因，不把unknown写成不支持 |
| 本轮路线 | Tripo生成 / Blender局部修正 / 有依据的Blender替代制作 |
| Blender范围 | 具体对象/属性/动作，预期改动与保护项；为何已有内容不能直接复用 |
| 完成与退出 | 可见改善、保护区及回归检查；失败后回到哪项Tripo选项或停止条件 |

相关功能另外记录ID、采用/跳过/待核实原因、输入限制、会失效的UV/材质/绑定等下游检查；复用当前路线文档，不另造全功能审批表。逐clip的专属动画评估应区分文字、视频与多阶段节点，选择与需求最匹配的一种，不强制全试。Studio参考生图、批量与多变体的执行适配边界见配方，不能为利用率绕过现有单run检查。

这是技能层的选路要求，执行器只校验既有计划、身份、预算和回执，不能自动认证“已充分评估Tripo”。不要用一段无证据的理由当作质量通过。

## 绑定与动作的优先顺序

1. 先逐个明确用户所需动作：主体、起止姿势、身体朝向、手掌/脚底要求、站姿或坐姿、原地或位移、单次或循环，以及已明确的速度和时长。已有答案复用，缺少影响选择的关键信息才询问，不拿“挥手”名称代替需求。
2. **骨骼绑定必须由Tripo完成。** 记录来源run/资产版本、原生文件哈希、骨架类型及骨名/层级。Blender只保留、核验和局部修正该骨架及权重，不把诊断代理骨架、自建骨架或Rigify当成替代绑定。无法取得有效Tripo绑定时暂停依赖它的动作制作，继续允许的排错；除非用户之后明确改变这一要求。
3. **先找Tripo对应案例/预设。** 记录检索词、候选名称/身份、完整预览和不匹配理由；检查坐/站、方向、手脚、循环及root。应用预设可能触发任务，核查实际UI、费用和既有授权后执行。
4. **没有合适预设时，尝试Tripo“创作专属动画”。** 先核实当前页面入口、输入要求、角色兼容性、报价及输出，按明确需求提交并验证结果。不把未查看、暂时登录失败或没有尝试写成“不支持”。功能确实不可用时保存证据；不臆造操作，不擅自切API。
5. **最后才自行制作动作。** 仅在预设不匹配、专属动画尝试不满足目标或经核实不可用时，记录结果与原因，在已经Tripo绑定的骨架上制作/重定向动作。不得借机重新自建绑定；现有Studio积分按持续授权使用；失败无改善时诊断换路，不无限重复尝试。
6. 导入后先按 [导入排错与版本展示](import-and-presentation.md) 核对原生骨架、蒙皮、动作槽、NLA、坐标与root，区分源动作缺陷与导入播放错误。骨架适用性和动作语义分别下结论。
7. 原生动作保留，修正版另命名。匹配动作的少量接触、朝向、幅度/节奏或局部权重问题可在Blender修正；这不等于绕过上面的顺序去重新生成整套动作。

需要上传修过结构的模型时，保留原母版、旧权重和动作，单独制作交换副本。外部文件可含骨架/动画，不代表Studio会完整沿用；新绑定后重新核对当前rig/motion证据。最终权重、刚性附件随动和动作精修放在最后一次必要的Tripo往返之后。仅纹理小改不强制重绑；需要保留旧精修动作时，另分支生成和映射的可行性须实测。

动画路线记录另须列出：用户动作需求、预设检索及匹配结果、专属动画run/结果或不可用证据、最终来源（preset / tripo_custom / local_on_tripo_rig）、Tripo骨架来源。每个clip分别记录，不能用一个动作的失败理由替代全部动作。

## 防止诊断变成默认自建生产

- 动画早期试验优先复用Tripo骨架和动作。缺少目标压力姿势时可在原生骨架副本上添加最小诊断姿势，不得据此演变为整套自建绑定。
- 没有Tripo骨架时不默认建立代理骨架推进动作生产；先完成或排查Tripo绑定。静态几何检查可独立继续。
- 同一缺陷在Blender连续两轮无实质改善，停止该策略并重新核查Tripo相关处理/替代预设、输入兼容和已获授权。diagnostic同样适用此选路停止规则，不因不计入修复失败而无限试验；底层计数语义保持不变。
- 局部修改若演变成整套权重替换、整套动作重做或整体重塑，先更新路线依据；骨架仍必须保留Tripo绑定来源。范围和费用已有授权时继续，不新增形式性批准；实质扩大任务范围时确认所缺范围；不为现有Studio积分重复请批。

## 验证边界

自动生成不等于质量通过。保留原来的几何、纹理通道、保护区、压力姿势、完整clip、真实速度/慢放、循环、导出回读及用户验收要求。未知提交先对账；不能为“Tripo优先”绕过未知状态、重复收费或切换API。能力矩阵是候选入口，具体型号/功能/价格依本次UI和结果确认。
