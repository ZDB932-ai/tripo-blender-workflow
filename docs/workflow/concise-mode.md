# 简洁工作流

默认：**制作 → 自动检查与必要修正 → 最终验收**。新任务用 autonomous + concise + progress_guarded。用户明确要求逐阶段确认时才用 guided。

## 代理自行完成

- 复用已明确的需求、参考和授权；只补真正缺失的信息。
- 选择执行路线、核对报价、补齐报告、修复可恢复记录、对账、诊断和中间审阅。不要把 blocked、缺字段或需要审阅直接翻译成“请用户批准继续”。
- concise 模式下，中间关卡和动画节奏由代理根据真实证据审阅；无需每阶段请示，也不得伪造用户批准。最终仍由用户验收。
- 默认只读 summary，按当前目标加载必要文档。只检查本次修改可能影响的部分；有验证过的复用证据就保留既有检查。
- 已有候选时，未选中的 planned 草稿保留但不阻挡本地工作；主动选择该 run 后仍正常走提交前检查。已提交、处理中或未知状态不能忽略或重放。

## 防止无效重复

- 同一来源、问题、假设和脚本已有完成的诊断，复用它；不同问题或实质不同的方法可以继续诊断。相同诊断两次执行失败先解决原因。
- 导出按来源、格式和用途分别处理；成功结束对应失败序列。相同脚本连续失败两次停止重复执行，修复脚本并核查原因后继续，不问增加次数。
- 修复连续无改善仍须诊断换路；跨缺陷连续六次无改善暂停新增制作，保留最佳成果，允许独立诊断。不要通过改名字、改注释或虚构改善绕过保护。
- 诊断成功不等于模型合格；候选变更的受影响检查、真实回执、来源核对和导出回读仍保留。

## 只在这些情况下找用户

真正缺失且无法推断的设计选择；登录或验证码等必须本人操作的访问问题；需要改变已明确的范围或质量要求；最终验收。一次集中说明问题、已尝试的恢复和具体所需输入，避免逐个字段提问。

summary.operator 的 responsibility 与 ask_user 标明当前审阅是否需要用户。agent 表示先由代理处理，不保证所有外部访问问题都能自动解决。

## 旧任务切换

复用用户已有简化要求，将真实指令存入资产目录 `work/concise-policy.json`：

```json
{"evidence":"用户明确要求简化流程，减少中间检查请示，代理自行处理内部恢复，保留最终验收"}
```

```powershell
node tools/workflow/work.mjs simplify ASSET work/concise-policy.json
```

保留历史、源文件、质量标准和已通过关卡；已有真实用户中间审阅仍有效。未完成执行、未知传输或已验收任务不能切换。不能用切换清零停滞计数。
