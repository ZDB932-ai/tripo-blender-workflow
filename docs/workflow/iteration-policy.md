# 按进展继续本地制作

新任务默认 `progress_guarded`：在已明确的任务范围内继续本地制作，不按累计批次数请求增加修改次数。质量标准、实际执行回执、候选保护、未知执行对账与最终验收不变。

## 自动决策

- 有验证过的改善：继续处理未满足的要求；达到标准即转入交付，不无限美化。
- 同一缺陷连续两次无改善：停止原策略，由代理检查证据、诊断并提出实质不同的方法。继续前仍需 strategy_review，不请用户批准数字次数。
- 跨缺陷累计连续六次制作无改善：停止新增制作，保留当前最佳候选，允许诊断与合规导出，报告具体未解决要求及尝试过的路线。改缺陷名、策略名、切换模式、重启会话均不清零。只有正式核验的 improved 结束停滞序列。
- 诊断按来源、问题、假设和脚本识别重复，完成的检查复用，不限制不同目的的诊断。导出按来源、格式和用途区分，成功结束历史失败序列；相同脚本连续两次执行失败先修复原因。详见 [简洁工作流](concise-mode.md)。
- 上述保护触发后，不问“再加几次”；需要用户介入时说明真正的选择，例如补充缺失参考、调整明确的设计要求或接受已披露限制。不得自动降低标准或将不合格资产标记完成。

这是一套本地执行与代理选路规则，不是能自动理解美术缺陷的算法。CLI 检查记录与证据；代理负责真实诊断和方法选择。诊断不会重置失败序列。

## 旧任务一次迁移

旧任务默认保留旧模式。用户已要求取消次数请批时，直接复用该指令作为 evidence，不重复询问。先完成未知执行对账，再写入相对资产目录的 `work/iteration-policy.json`：

```json
{
  "mode": "progress_guarded",
  "evidence": "填写已有的真实用户指令，说明在任务范围内按进展继续，而不逐次请求增加次数"
}
```

```powershell
node tools/workflow/work.mjs iteration-policy ASSET work/iteration-policy.json
node tools/workflow/work.mjs summary ASSET
```

命令使用资产锁，不允许在未完成批次期间切换。它只修改本地次数策略并记录事件，保留历史次数、旧上限、源文件、质量标准、停止策略和审阅。此模式下历史总上限及分类上限不参与阻塞；不会改动 Studio 积分策略。用户确实要求固定次数时，用同一入口设置 `explicit_budget`，恢复原有数字上限。

配置质量标准仍需真实任务依据，但不要为了放宽次数而调用 configure：它会让现行质量关卡失效。次数策略有专用入口。
