# Studio 后处理配方入口

费用：任务范围内默认自主使用现有 Studio 积分，按项目 docs/workflow/credit-policy.md 执行，不逐次请批。参考/质量审阅、本地返工限制、未知任务对账仍保留。

统一功能索引为项目 `docs/workflow/studio-capabilities.md`，详细步骤为 `docs/workflow/studio-recipes.md`。按下表只读取当前问题对应配方；不再维护另一套重复步骤。每项固定源版本，费用纳入既有授权或形成可审阅的新计划。结果另存run，不覆盖已验收版本。

| 功能ID | 配方 | 关键分流 |
|---|---|---|
| M01–M05 | 3：局部几何、分件与补全 | 先查兼容源；快速封口与AI补全不同，当前分件排除四边/已绑定 |
| M06–M07/M10 | 3：拓扑与部件 | 三角/四边预算不同；按需局部处理，检查装配 |

| A01–A07 | 6：绑定与动作 | 预设→专属文字/视频/多阶段→最后本地动作；保留Tripo骨架 |

## 操作记录

在新run的plan中记录 operation、source_run_id、source_asset_url、source_version（未知为null）、source_file/source_sha256、目标改变、必须保留内容、UI参数、报价、输出、成功标准和停止条件。

新结果加载成功才进入qa_review。不要只因后处理按钮点击成功就更新源版本；输入和输出都应有可辨认的网页版本或导出哈希。页面没有版本机制时先导出源文件备份，再在实际支持的复制流程上继续；若可能不可逆覆盖且用户未授权，完成计划后解释具体风险并请批。

提交失败/未知沿用generate恢复规则。重做、模型转换、升级纹理和试用消耗不是普通只读检查，不能从历史45积分授权推导权限。仅导出已有产物失败则重试下载，不重复执行上游处理。

官方来源与页面差异见项目 `docs/research/tripo-studio-2026-09-27.md`。文档、UI、执行和质量证据分别记录；不能把API参数当Studio控件。保留已合格结果，不为了用遍功能反复重拓扑或重绑。
