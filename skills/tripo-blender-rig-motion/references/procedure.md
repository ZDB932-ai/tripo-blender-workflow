# 按需操作说明

共享状态、命令与 schema 只以项目 `tools/workflow/PRODUCTION.md` 为准。本文提供领域操作细节，不覆盖当前执行器。版本、报价与控件按实际运行核实。

- 明确目标骨架/引擎、rest pose、角色肢体类型、动作清单、帧率、时长、loop/root motion、面部需求及交付格式。先准备方案，缺失关键动作意图时询问；不随意生成“待机走跑”替代用户需求。
- 可先执行只读绑定就绪诊断，不要求纯绑定用户提供clip参数。先检查polish的静态几何与rest pose；发现粘连等实际几何缺陷时回几何诊断/修整。新标准的deformation_readiness在rig阶段用实际压力姿势验收，尚未创建骨架时不能以缺少变形测试阻止创建rig。旧标准按其冻结关卡执行。基础压力姿势是验证工具，不等于已交付动作；分别报告预检、绑定变形、实际clip和导出回读的完成度。
- 按 PRODUCTION.md“Blender 执行路径”执行：实时 MCP 核对连接/场景；后台核对版本和已归档源，不要求 live MCP 接通。两条路径共用执行回执；未知批次先对账，不跨路径重放。母版另存工作版本。保留几何稳定版本，先检查腋下/关节边流/手脚分离；不适合变形时返回polish。自动重网格或三角转四边不能自动证明适合蒙皮。
- 先评估Tripo自动绑定及当前动作库能否满足目标；适用且授权覆盖时由refine/preflight/generate执行，再导入本阶段检查。已有合格骨架/clip先复用、映射与修正，不默认删除重建。缺少骨架/clip时按 docs/workflow/tripo-first.md 和 `docs/workflow/roundtrip.md` 先走Tripo对应能力；必要结构修正在上传前完成，精修权重与动作在最后一次往返后完成。不得以本地代理或自建骨架替代Tripo绑定。预设不匹配先尝试“创作专属动画”，最后才在原生骨架上自行制作动作，按clip记录证据。复杂面部、非标准动作或指定接触动作按选路顺序评估后，可在Tripo骨架上定制动作，并写明理由；不能把Tripo动作存在当作重定向和引擎播放已通过。
- 收到上传处理或重新绑定结果先只读比较源与回传的几何、分件、UV、材质、骨架、权重及动画；动画名称或 clip 数量不能证明骨骼通道完整。外部精修权重和旧动作不能默认保留，也不从旧版继承 rig/motion 通过。原母版与交换副本保持独立，确认新结果的适用属性后再接入正式工作版本。
- 骨骼位置、朝向、层级、命名、root和deform骨按目标建立；控制rig与最终变形rig分开。此流程不使用Rigify重新绑定替代Tripo骨架；用户后续明确改变范围时另行处理。
- 自动权重仅作起点。检查未加权顶点、归一、异常跨部件影响和目标要求的最大骨影响数；不能全角色硬套同一阈值。以抬臂、弯肘、屈膝、扭转和必要极端姿势验证体积、穿插及权重，必要时修正权重或形态键。有可拆卸刚性附件时按 brief 检查它是否随角色正确运动及保持形状；只在实测出现压缩、拉伸或装配错误时修正为适用的刚性绑定，不把本案例的背包缺陷当作通用必修项。
- “本轮未改动”的权重不等于已通过；保护区要覆盖手臂和腿部动作，发现保留躯干被远端骨骼牵连时记录顶点/影响证据，局部重新评估。关节附近合理的混合权重不能因语义检测简单清零。侧视双腿遮挡时增加单侧或斜视证据。
- 绑定前用实际网格顶点/区域固定保护区与基准姿势，检查局部动作是否异常带动脸、肚皮、脚等无关区域。除关节拉伸外记录保护区位移、宽度/轮廓变化及同机位对比；先确定本资产测试阈值，不将示例阈值当通用标准。归一通过不能覆盖保护区失败。tools/workflow/deformation_guard.py 可评价相同拓扑的区域数据；换拓扑后必须重建映射，不能沿用顶点索引。
- 连续同策略失败后比较Tripo原生骨架/权重或有明确区域选择的局部修复，不反复修改粗略空间阈值。隔离诊断可验证失败原因，不得冒充rig/motion通过；将诊断交换链路通过与成品质量通过分别记录。实时 MCP 使用后仅在无未决传输/执行时恢复展示场景；后台任务不改变用户 live 场景。
- 每批修改按所选路径回读审计并查看视觉证据；冻结条件比较使用独立后台采图。动作制作/重定向只用授权来源，检查每个clip的完整播放、接触与足滑、根轨迹、循环首尾、帧率；压力姿势通过不代表实际动作通过。
- 记录控制约束、驱动、形态键和导出器支持范围，必要时在导出副本烘焙可交换动画，保留编辑rig。Studio 导出逐 clip 明确核对勾选和骨骼/纹理设置；不能假定当前播放动作会自动被勾选。导出后在干净临时场景/文件重新导入并播放，比较 clip 数量、时长、实际骨骼/根节点通道、骨架、运动与外观。未回读不能宣称动作交付通过。
- rig和适用的motion分别按review_mode决定AI或用户审阅，技术失败/未测项不能跳过；纯绑定输出rig-report.json、压力姿势证据与.blend母版，不要求实际clip；动作需求另输出motion-report.json与预览。新增远程操作须符合任务范围，现有Studio积分默认自主使用，不逐次请批；本地返工仍受轮数上限约束。
- 技术和审阅通过交deliver；指定引擎再交engine。记录未测的面部、布料或物理，不将“有骨架”写成所有动作可用。

需要相似角色故障示例时读取项目 docs/cases/character-diagnostics.md；不要无条件加载历史案例。
